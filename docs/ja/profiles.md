# プロファイル：1 台のコンピューターで複数のハブ

[← Interlatch](../../README.ja.md) · [ドキュメント一覧](README.md)

コンピューターが参加できるハブは一つです。自分のプロジェクトと取引先のプロジェクトのように、それぞれにハブがある複数のチームで働くときは、**プロファイル**でセッションを分けます。フォルダーはどれか一つのプロファイルのもので、セッションが届くハブは多くても一つです。

- **Personal** は、いま使っているプロファイルです（`~/.interlatch`）。これまでどおり、すべてのエージェントのすべてのセッションを記録・分析します。このコンピューターにあるすべてのものの元のコピーです。
- **名前付きプロファイル**（たとえば Acme）は、いくつかのフォルダーと、必要なら git リモートがパターンに合うリポジトリを持ちます。そのセッションは Personal のハブには送られず、のちに Acme のハブにだけ送られます。

!!! note "段階的に作っています"
    この最初の段階では、各セッションの持ち主を決め、名前付きプロファイルのセッションを Personal のハブに送らないようにします。名前付きプロファイルが自分のハブに送る機能はまだありません。また、Personal のフォルダーで動くエージェントには、MCP サーバーを通じてプロファイルのセッションがまだ見えます。どちらも次の段階で入ります（[このあと入るもの](#このあと入るもの)）。

## プロファイルを作る

```bash
interlatch profile create Acme --owns ~/work/acme
interlatch profile create Globex --owns ~/clients/globex --remotes 'github.com/globex-inc/*'
```

`--owns` は、そのフォルダーとその下のすべてをプロファイルのものにします。`--remotes` は、git リモートがパターンに合うリポジトリを、どこにクローンされていてもプロファイルのものにします。どちらも繰り返して複数指定できます。プロファイルのフォルダーの中で見つかったリポジトリは、ほかの場所のクローンもそのプロファイルのものになります。

そのフォルダーですでに記録されたセッションは、プロファイルに移ります。Personal のハブがすでに持っているものは、ハブにコピーが残ります。そのため、ハブが一部を持っているときは何も変えず、その数を表示します。先に取り戻す（ハブに追加したフォルダーなら `interlatch hub remove-folder <folder>`、そうでなければハブの管理者に削除を頼む）か、`--leave-on-hub` を付けてそのまま移してください。`--dry-run` を付けると、何も変えずに移るものだけを表示します。

プロファイルごとに専用のフォルダー `~/.interlatch/profiles/<id>` ができ、設定、コンピューターの ID、ダッシュボードのポート（11525、11526、…）を別に持ちます。

## セッションの持ち主の決まり方

次の順に、最初に当てはまったもので決まります。

1. **持ち主は変わりません。** 一度決まると、変わるのはフォルダーを移したとき（`profile own`、`choose`）だけで、新しいルールでは変わりません。
2. **フォルダー。** セッションを含む、持ち主のいるフォルダーのうち最も長いもの、またはあなたの選択（下記）で決まります。ほかのプロファイルの `--remotes` のパターンもそのリポジトリに合うときは、あなたの選択を待ちます。
3. **リポジトリ。** git リモートがプロファイルのパターンに合うか、そのリポジトリがプロファイルのフォルダーで見つかったことがあれば、そのプロファイルのものです。二つのプロファイルに当てはまるときは選択を待ちます。
4. **それ以外は Personal。** claude.ai や ChatGPT から取り込んだチャットも含みます。

フォルダーがどう決まるかを確かめるには：

```bash
interlatch profile where ~/work/acme/app
```

## 選択を待つフォルダー

二つのプロファイルのものになりうるセッションは**選択を待ちます**。Personal は記録・分析を続けますが、あなたが選ぶまでどのハブにも送られず、どのプロファイルのものにもなりません。

```bash
interlatch profile waiting
interlatch profile choose ~/work/shared-lib Acme       # または personal
```

選択はあなたの答えです。そのフォルダーとその下のすべてが決まります。ただし、中にもっと狭いフォルダーを持つプロファイルがあれば、そちらが優先されます。

## フォルダーを移す

| 目的 | 実行するコマンド |
| --- | --- |
| プロファイル、そのフォルダーとセッションの一覧 | `interlatch profile list` |
| プロファイルにフォルダーを加える（これまでのセッションごと） | `interlatch profile own <folder> <profile>` |
| フォルダーをプロファイルから外す | `interlatch profile disown <folder>` |
| プロファイルを削除する | `interlatch profile remove <profile> [--delete-data]` |
| 任意のコマンドをプロファイルで実行する | `interlatch --profile <profile> <command>` |

`disown` と `remove` は、フォルダーを勝手に Personal に戻しません。そのセッションはあなたの選択を待つので、取引先のフォルダーが誤って Personal のハブに共有されることはありません。`remove` は、`--delete-data` を付けない限りプロファイルのフォルダーを残します。

## プロファイルと共有

- **ナレッジだけ。** どのプロファイルも、要約とプロジェクトのナレッジだけを共有し、トランスクリプトは送りません。トランスクリプトを送るとすべてのプロファイルのセッションが含まれてしまうため、名前付きプロファイルがある間は Personal もトランスクリプトを送らず、`interlatch profile create` は先に切り替えるよう求めます：`interlatch config set hub.share knowledge`。
- **ハブ一つにプロファイル一つ。** ほかのプロファイルがすでに送っているハブへの参加は、何も送る前に断られます。
- **Personal のハブ**には Personal のセッションだけが届きます。ハブへのあいさつで伝えるリポジトリやフォルダーにも、ほかのプロファイルのものは含まれません。

## 保存場所

`~/.interlatch/profiles.toml` に、プロファイル、そのフォルダーとパターン、あなたの選択が入ります。読めるのはあなただけです。このファイルが読めないときは、直すまで Personal はハブに何も共有しません。

最初のプロファイルを作ると、Personal のアーカイブに各セッションの持ち主を記録する `session_owner` テーブルができます。プロファイルのないアーカイブは変更されません。

## このあと入るもの

1. **エージェントには自分のプロファイルだけが見える。** MCP サーバーとセッション開始時のコンテキストで、Personal のフォルダーのエージェントには Personal のセッションだけを、プロファイルのフォルダーのエージェントにはそのプロファイルのセッションだけを見せます。
2. **プロファイルごとに自分のハブと共有する。** 名前付きプロファイルが Personal からセッションをコピーし、自分のハブと共有します（`interlatch --profile Acme hub join …`）。フォルダーを移すと、それまでのハブからセッションを取り戻します。
3. **ウィンドウとダッシュボード。** プロファイルごとに名前の付いたウィンドウ、メニューバー、ダッシュボードの「プロファイル」と「選択待ち」のカード。
