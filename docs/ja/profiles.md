# 1 台のコンピューターで複数のハブ

[← Interlatch](../../README.ja.md) · [ドキュメント一覧](README.md)

コンピューターが参加できるハブは一つです。自分のプロジェクトと取引先のプロジェクトのように、それぞれにハブがある複数のチームで働くときは、**プロジェクトのグループ**を、それぞれが属するハブにつなぎます。そうすると、各フォルダーのセッションは一つのハブにだけ届き、そこで作業するエージェントにはそのハブのものだけが見えます。

- **Personal**（`~/.interlatch`）は、これまでどおり、すべてのエージェントのすべてのセッションを記録・分析します。このコンピューターにあるすべてのものの元のコピーで、自分のハブに送ることもできます。
- **ほかのハブ**には、ここでの名前（たとえば Acme）を付けます。そのハブにつないだグループのセッションが届きます。読むのは Personal のアーカイブで、コピーは作らず、分析も二度しません。

## ハブを追加してグループをつなぐ

1. ハブの管理者から受け取った招待コードでハブを追加します（[チームのハブに参加する](join-a-hub.md)）。

    ```bash
    interlatch hubs add Acme https://hub.acme.example --code XXXX-XXXX-XXXX
    ```

2. そのハブに属するフォルダーのグループを作ります。ダッシュボードの「プロジェクト」ページにあるグループも使えます。

    ```bash
    interlatch group create "Acme work" --folder ~/work/acme --folder ~/clients/acme-site
    ```

3. グループをハブにつなぎます。

    ```bash
    interlatch group connect "Acme work" Acme
    ```

グループのフォルダーですでに記録されたセッションは Acme に移り、それ以降は Acme のハブに送られます。Personal のハブがすでに持っているものは、先にそのハブが取り下げます（[移すとハブから取り下げる](#moving-takes-sessions-back)）。`--dry-run` を付けると、何も変えずに、移るものと、そのうちハブが持っている数を表示します。

**ダッシュボードでは：** **設定 › ハブ**に Personal のものを含むすべてのハブが並び、ハブの追加（名前、アドレス、招待コード）もここで行います。ハブごとにタブがあり、どのハブも同じ構成です。送信がうまくいっているか、**今すぐ共有**、ハブのダッシュボード、**ハブのプロジェクト**（ここのフォルダーでハブのプロジェクトに参加する、抜ける）、そのハブと何を共有するか、です。グループのページの**送り先**で、そのグループのセッションを送るハブを選びます。**プロジェクト**のサイドバーでは、ハブにつないだグループにそのハブの名前が表示され、選択を待つフォルダーが先頭に並びます。

ほかのコンピューターと同じく、ハブに送られるのは、そのハブのプロジェクトに追加したフォルダーのものだけです（`interlatch --hub Acme hub add-folder ~/work/acme/app --project App`）。`--all-folders` を付けて参加した場合は別です。

## グループで決まる

つないだグループに入っているものが、そのハブに送られます。グループのフォルダーとその下のすべて、そして「プロジェクト」ページで手で入れたプロジェクトです。グループを変えると、これまでのセッションも含めてハブがそれに従います。

| すること | そこにあるセッション |
| --- | --- |
| つないだグループにフォルダーを加える、プロジェクトを入れる | そのハブに移る |
| つないだグループからプロジェクトを外す | あなたの選択を待つ（下記）。勝手に Personal には戻らない |
| つないだグループのフォルダーの中に、どのハブにもつながないグループを作る | あなたの選択を待つ |
| つないだグループのフォルダーの中のグループを、別のハブにつなぐ | そのハブに移る。狭いほうのグループが優先 |
| グループの接続を外す（`interlatch group disconnect "Acme work"`） | あなたの選択を待つ |

<a id="moving-takes-sessions-back"></a>

### 移すとハブから取り下げる

セッションが置かれるハブは一度に一つです。変更でセッションがあるハブから離れるとき（別のハブへ、またはあなたの選択待ちへ）、そのハブは、このコンピューターが送ったものを取り下げます。要約とナレッジが、そのハブとチームストアから消えます。これは新しいハブに何かを送る前に行います。あとでそのハブに戻すと、もう一度送られます。

ハブに届かないとき、またはこのコンピューターがまだそのハブに送っている最中のときは、何も変えず、理由を表示します（ダッシュボードでも同じ）。あとでやり直すか、そのまま移してください（`--leave-on-hub`、またはダッシュボードの確認で **OK**）。その場合、次にこのコンピューターがそのハブに送るときに取り下げます。このバージョンより古いハブは取り下げができません。ハブを更新するか、そのまま移してください。そのハブのコピーは残ります。

ハブの削除（`interlatch hubs remove`）では何も取り下げません。先にそのハブから抜けてください。

一つのフォルダーが属せるハブは一つです。二つのハブのグループを同じフォルダーにつなぐことはできません。

## 選択を待つフォルダー

複数のハブのものになりうるフォルダーや、グループが手放したフォルダーは**選択を待ちます**。Personal は記録・分析を続けますが、あなたが選ぶまで、どのハブにも送られず、どのエージェントにも見えません。

```bash
interlatch group waiting
interlatch group choose ~/work/acme/notes Acme       # または personal
interlatch group where ~/work/acme/app               # フォルダーがどのハブに行くか、その理由
```

**設定 › ハブ**にも一覧があり、それぞれに**選ぶ**ボタンがあります。**ホーム**の**あなたの対応待ち**にも表示されます。あるフォルダーが選択待ちにしているプロジェクト（つないだグループの中にある、どのハブにもつないでいないグループ）は、そのフォルダーの下にまとめて表示します。

## エージェントに見えるもの

Interlatch がエージェントに渡すもの（[MCP サーバー](mcp.md)のツールと、セッション開始時のメモ）は、エージェントが動くフォルダーで決まります。

- **ハブにつないだグループのフォルダーでは：** そのハブのセッション、ナレッジ、ナレッジベース、チームメイトのナレッジだけ。
- **それ以外の場所では：** Personal のものだけ。
- **選択を待つフォルダーでは：** 何もありません。MCP のツールは、そのフォルダーがあなたの選択を待っていると伝えます。

すべてのプロジェクトをまとめて作るもの（全体のプレイブック、ほかのハブのプロジェクトにも出てくる用語集の用語、テーマ、週次レビュー）は、ほかのハブがある間はエージェントに見せません。ダッシュボードには引き続きすべて表示されます。

すべてのフォルダーでエージェントが読むユーザーレベルの指示ファイル（`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`）に Interlatch が提案する行は、Personal のナレッジからだけ作ります。ほかのハブのセッションで得たナレッジは、そのプロジェクト自身のファイルに提案します（[提案](suggestions.md)）。

## コマンド

| 目的 | 実行するコマンド |
| --- | --- |
| ハブとそのグループの一覧 | `interlatch hubs` |
| ハブを追加して参加する | `interlatch hubs add <name> [<address> --code <code>] [--all-folders]` |
| ハブを削除する | `interlatch hubs remove <name> [--delete-data]`（先に抜けておく：`interlatch --hub <name> hub leave`） |
| グループと送り先の一覧 | `interlatch group list` |
| グループを作る、フォルダーを変える | `interlatch group create <name> --folder <folder>…`、`group add-folder` / `remove-folder <group> <folder>` |
| グループをつなぐ、外す | `interlatch group connect <group> <hub>`、`group disconnect <group>` |
| ほかのハブのハブコマンドを実行する | `interlatch --hub <name> hub …` / `push` / `config …` |

`interlatch push` とバックグラウンドの処理は、Personal のハブ、次にほかの各ハブへ送ります。記録、分析、ダッシュボードは Personal が行います。`--hub` を付けて実行できるのは `hub`、`push`、`config` だけです。

## 複数のハブとの共有

- **ナレッジだけ。** どのハブにも、要約とプロジェクトのナレッジだけを送り、トランスクリプトは送りません。トランスクリプトを送るとすべてのハブのセッションが含まれてしまうため、ほかのハブがある間は Personal もトランスクリプトを送りません：`interlatch config set hub.share knowledge`。
- **各ハブに一度だけ。** このコンピューターがすでに送っているハブへの参加は、何も送る前に断られます。
- **自分の ID。** ハブごとにトークンとコンピューターの ID が別なので、二つのハブが ID でこのコンピューターを突き合わせることはできません。ただし、どのハブにもコンピューターの名前は表示されます。ハブに見せる名前は `~/.interlatch/profiles/<id>/machine.json` で変えられます。
- **自分のチームメイト。** ハブから届いたチームメイトのナレッジはそのハブのものとして保存し、エージェントにはそのフォルダーでだけ見せます。一つのハブから抜けても（`interlatch --hub Acme hub leave`）、消えるのはそのハブのものだけです。
- **Personal のハブ**には Personal のセッションだけが届きます。ハブへのあいさつで伝えるリポジトリやフォルダーにも、ほかのハブのものは含まれません。

## 保存場所

`~/.interlatch/profiles.toml` に、ほかのハブ、それぞれにつないだグループ、そこから決まるフォルダー、あなたの選択が入ります。読めるのはあなただけです。このファイルが読めないときは、直すまでどのハブにも何も共有しません。ハブごとに専用のフォルダー `~/.interlatch/profiles/<id>` があり、トークン、コンピューターの ID、共有の状態が入ります。

最初にほかのハブを追加すると、Personal のアーカイブに各セッションの属するハブを記録する `session_owner` テーブルができます。ほかのハブのないアーカイブは変更されません。

**0.28.1 から：** `interlatch profile` は `interlatch hubs` と `interlatch group` になり、`--profile` は `--hub` になりました（古い名前も使えます）。`--owns` でプロファイルに与えたフォルダーは、そのハブのものとして残ります。
